## How it works

1. Your server calls Bison with two tokens: a machine token for your backend and the signed-in user's access token. Bison returns an iframe URL and a launch token.
2. Your page loads the iframe from that URL.
3. The iframe posts `bison.embed.launchReady`. Your page answers with `bison.embed.launchToken`.
4. The iframe exchanges the launch token for a session. A launch token works once and expires within 30 seconds.
5. The iframe calls Bison directly with that session. Your page and your server stay out of the data path.

Your page owns navigation. It picks the first screen with `initialPath` and shows another screen by launching a new iframe. See [Screens and navigation](/screens/). The one exception is JIB setup: when the user finishes it, the iframe moves to JIB itself and posts `bison.embed.viewChanged`.

## What you need

| Value | Comes from | Used for |
| --- | --- | --- |
| API base URL | Bison, per environment | Where your server sends launch requests |
| Machine credential | Bison | Your server mints short-lived Clerk machine tokens with it |
| Embed origin | Bison, per environment | The origin of `iframeUrl`. Use it in your CSP `frame-src` and as the `postMessage` target |
| User access token | Your identity provider | Tells Bison which user and organization is launching |
| Site origin | You, to Bison | The exact origin of the page that hosts the iframe, for example `https://app.example.com` |

Before your first launch, Bison configures its side for each environment:

- Your identity provider's issuer, and the audience your user tokens carry.
- Your site origin, in the places the embed checks it: the list of origins allowed to launch, and the embed's own configuration, which Bison sets when it builds the embed. Each Bison environment trusts one host origin.
- A machine credential for your backend.
- A link from each of your users and organizations to a Bison user and working interest owner account. Bison creates these links. A launch for a user or organization with no link fails with `404` and `external_identity_not_mapped`. Other identity failures use their own codes: see [Launch API](/launch-api/#errors).

## Step 1: Start a session

Run this on your server. It needs both tokens, and neither may reach the browser.

1. Mint a machine token. Bison accepts opaque Clerk machine-to-machine tokens that expire within 300 seconds. Always set `secondsUntilExpiration`: Clerk's default is a token that never expires, and Bison rejects it.
2. Take the signed-in user's access token from your identity provider. Bison verifies it, so it must meet the rules in [Authentication](/authentication/#user-access-token).
3. Call the launch endpoint.

```js title="server.js"
import { createClerkClient } from '@clerk/backend';

const machineSecretKey = process.env.BISON_MACHINE_SECRET_KEY;
const clerk = createClerkClient({ machineSecretKey });

app.post('/bison/launch', async (req, res) => {
  try {
    const machine = await clerk.m2m.createToken({
      machineSecretKey,
      secondsUntilExpiration: 300,
    });

    const response = await fetch(
      `${process.env.BISON_API_URL}/partner/energylink/embed-sessions`,
      {
        method: 'POST',
        headers: {
          'content-type': 'application/json',
          authorization: `Bearer ${machine.token}`,
          'x-energylink-user-authorization': `Bearer ${req.user.accessToken}`,
        },
        body: JSON.stringify({
          audience: 'working_interest_owner',
          parentOrigin: process.env.SITE_ORIGIN,
          initialPath: req.body.initialPath,
        }),
      },
    );

    if (!response.ok) {
      console.error('Bison launch failed', response.status, await response.text());
      return res.status(502).json({ error: 'launch_failed' });
    }

    const { data } = await response.json();
    res
      .set('cache-control', 'no-store')
      .json({ iframeUrl: data.iframeUrl, launchToken: data.launchToken });
  } catch (error) {
    console.error('Bison launch error', error);
    res.status(502).json({ error: 'launch_failed' });
  }
});
```

Replace `req.user.accessToken` with however your server holds the current user's access token, and the environment variable names with your own. Log Bison's status and `errorCode`, as the sample does: they tell you which check failed. Try the same request without code, using the two tokens from the steps above:

```bash
curl -X POST "$BISON_API_URL/partner/energylink/embed-sessions" \
  -H "content-type: application/json" \
  -H "authorization: Bearer $MACHINE_TOKEN" \
  -H "x-energylink-user-authorization: Bearer $USER_ACCESS_TOKEN" \
  -d '{"audience":"working_interest_owner","parentOrigin":"https://app.example.com","initialPath":"/wio/dashboard"}'
```

The response:

```json
{
  "success": true,
  "message": "Success",
  "data": {
    "iframeUrl": "https://<embed-origin>/embed",
    "launchToken": "<43-character token>",
    "expiresAt": "2026-10-07T07:15:30.482Z",
    "audience": "working_interest_owner",
    "module": "payments"
  },
  "errors": [],
  "timestamp": "2026-10-07T07:15:00.482Z",
  "traceId": null
}
```

- Use `iframeUrl` as returned. It carries no token and no screen. The first screen comes from `initialPath`.
- `launchToken` works once and stops working at `expiresAt`, at most 30 seconds after the call. That time includes the iframe loading, so create the iframe straight after the launch call.
- Take `parentOrigin` from your configuration, never from the request. It must be the exact origin of your page.
- Send `Cache-Control: no-store` to your browser. The response carries a credential.

The full request, response and error reference is in [Launch API](/launch-api/).

## Step 2: Load the iframe and answer `launchReady`

Your page creates the iframe and answers one message. The iframe posts `bison.embed.launchReady` once per handshake, when it is ready for a token. It doesn't retry, so attach your listener before you set `src`.

```js title="page.js"
const SANDBOX =
  'allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox allow-downloads';

export async function openBison(container, initialPath) {
  let stopFrame = () => {};
  let stopped = false;
  let quickFailures = 0;

  async function launch() {
    const res = await fetch('/bison/launch', {
      method: 'POST',
      headers: { 'content-type': 'application/json' },
      body: JSON.stringify({ initialPath }),
    });
    if (!res.ok) throw new Error('Launch failed');

    const { iframeUrl, launchToken } = await res.json();
    if (stopped) return;

    const embedOrigin = new URL(iframeUrl).origin;
    const startedAt = Date.now();

    const frame = document.createElement('iframe');
    frame.title = 'JIB Pay';
    frame.setAttribute('sandbox', SANDBOX);
    frame.style.cssText = 'display:block;width:100%;height:100%;border:0';

    let sent = false;

    const onMessage = (event) => {
      if (event.origin !== embedOrigin || event.source !== frame.contentWindow) return;
      const type = event.data?.type;

      if (type === 'bison.embed.launchReady' && !sent) {
        sent = true;
        frame.contentWindow.postMessage(
          { type: 'bison.embed.launchToken', launchToken },
          embedOrigin,
        );
      } else if (type === 'bison.embed.sessionInvalidated') {
        stopFrame();
        // Stop after three quick failures in a row instead of looping forever.
        quickFailures = Date.now() - startedAt < 60_000 ? quickFailures + 1 : 0;
        if (quickFailures < 3) launch().catch(console.error);
      }
    };

    stopFrame = () => {
      window.removeEventListener('message', onMessage);
      frame.remove();
    };

    window.addEventListener('message', onMessage);
    frame.src = iframeUrl;
    container.replaceChildren(frame);
  }

  await launch();

  // Closes the iframe and stops any automatic relaunch.
  return () => {
    stopped = true;
    stopFrame();
  };
}
```

Five rules keep this working:

- Attach the listener before you set `src`. A `launchReady` that arrives before your listener exists is lost, and the iframe stays on `Opening JIB Pay`.
- Check `event.origin` against the embed origin and `event.source` against the iframe's window.
- Reply only to `launchReady`, only to the embed origin, never to `'*'`, and at most once per launch token.
- Answer every `launchReady` with a freshly issued token. The iframe accepts the first valid token of each handshake and sends it to Bison once, with no automatic retry. If you reply with a used token, the iframe loops between `launchReady` and `sessionInvalidated`.
- Your page's origin must be the origin Bison configured in the embed. If it differs, the browser drops the iframe's messages, your page never receives `launchReady`, and the iframe stays on `Opening JIB Pay`. Ask Bison to confirm the embed's origin.

Every message your page can send to or receive from the iframe is listed in [Messages](/messages/).

## Step 3: Handle expiry

A session lasts at most 60 minutes and is never renewed in place. When it ends, or when Bison rejects it, the iframe posts `bison.embed.sessionInvalidated` and then asks for a fresh token with another `launchReady`. You have two ways to recover:

- **Relaunch.** Remove the iframe, run Step 1 again and mount a new iframe. The sample above does this, and it starts again from the `initialPath` you sent.
- **Answer in place.** Run Step 1 on your server and reply to the next `launchReady` with the new token. The iframe shows `Opening JIB Pay` while it waits, with no time limit, and keeps the screen the user was on.

Both options need a current user access token on your server. Refresh it first if it has expired.

## Frame requirements

**Content Security Policy.** If your page sends one, allow the embed origin:

```http
Content-Security-Policy: frame-src https://<embed-origin>;
```

**Size.** The embed fills the iframe and scrolls inside it. It never reports a height, so give the iframe a definite height, or stretch it in a flex or grid layout.

**Sandbox.** You don't need a `sandbox` attribute. If you add one, use the set the reference host ships:

| Token | Why the embed needs it |
| --- | --- |
| `allow-scripts` | The embed is a script-driven web app |
| `allow-same-origin` | The iframe calls Bison as itself and keeps a setup draft in `sessionStorage`. Without this token its origin is opaque and those calls fail. Its messages also arrive with `event.origin` set to `'null'`, so your origin check ignores `launchReady` |
| `allow-popups`, `allow-popups-to-escape-sandbox` | Bank linking opens a popup with `window.open`. `allow-popups` permits it. `allow-popups-to-escape-sandbox` lets the popup run without your sandbox's restrictions, as in the reference host |
| `allow-downloads` | Invoice and report downloads |
| `allow-forms` | Form submission inside the app. The reference host includes it |

**Popups.** Bank linking opens a popup window from the embed origin. The user's browser must allow it.

**HTTPS.** Serve your page over HTTPS. Launch rejects a `parentOrigin` that is not HTTPS, except `localhost`, and card entry does not load in a frame whose referrer is plain HTTP.
